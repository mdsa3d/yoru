# Neon Rash v3 — Rival AI / Laya Depth (ROADMAP §4) — Implementation Spec

## 0. Summary of current system

`src/rivals.js` holds a `Director` that re-evaluates one global `encounter` (`recover`/`balanced`/`pressure`) every .75 s with a 6 s dwell, where fairness guardrails (health < 32 or damage within 5 s ⇒ `recover`) unconditionally override any Laya-supplied encounter; `controlRival(a,i,p,obstacles,director,dt)` then picks one of four tactics per rival on a ~.10–.20 s think tick, purely from `gap = p.s - a.s`, `PERSONALITIES[i%3]` and the shared Director state — rivals have zero awareness of each other. `DecisionClient.tick` POSTs a flat state blob to `/api/decision` at most every .8 s with a 900 ms abort, 1.6 s staleness rejection and 4 s failure backoff, degrading to `'LAYA OFFLINE / LOCAL AI'`; `server/laya-worker.mjs` answers with exactly `{tactic,encounter}` from two `systemOne` choice fields. Rivals are spawned in `main.js:initializeActors()` as 3 actors with `target=(air?bike.vair*.74:bike.vmax*.84)+i*(air?2.4:1.9)` — they do **not** use `BIKES` physics at all, only this scalar `target` plus `profile.pace`.

**Global rule for this whole spec:** every addition must be inert when its inputs are absent. `Director.update` and `controlRival` are called in tests with no `field`, no `a.pi`, no `director.aggression`; every new code path must take the pre-existing branch in that case. Nothing at module scope may touch `document`/`window`/`localStorage`.

## A. Encounter / tactic variety

### A.0 Enum changes (`src/rivals.js`, top of file)

```js
export const TACTICS=['race','overtake','defend','yield','slipstream','block','bait'];
export const ENCOUNTERS=['recover','balanced','pressure','duel'];
export function validDecision(d){return !!d&&TACTICS.includes(d.tactic)&&ENCOUNTERS.includes(d.encounter)}
```
`validDecision` keeps the same arity/shape and stays the shared client+server validator (`server/decision-service.mjs` imports it). Extra keys on `d` remain ignored.

### A.1 Tactic `slipstream`

*Feel:* the rival tucks into the wake of whatever is directly ahead, sits there, then pops out.

Computed inside the `if(a.think<=0)` block, after `gap` is available. It needs the actor directly ahead — supplied by the survey pass (§B) as `field.aheadOf[i]` (`{s,x,v}` or `null`); when `field` is absent, fall back to the player:

```js
const lead=field?.aheadOf?.[i]??(gap>0?{s:p.s,x:p.x,v:p.v}:null);
const leadGap=lead?lead.s-a.s:Infinity;
```
Trigger (evaluated before the existing overtake test):
```js
const canDraft=!!lead&&leadGap>3.5&&leadGap<17&&Math.abs(lead.x-a.x)<2.2&&director.encounter!=='recover'&&(a.draftTime||0)<1.8;
```
Effect:
- `tactic='slipstream'`; `a.draftTime=(a.draftTime||0)+a.think` (accumulates only while drafting; reset to 0 on any think tick where `canDraft` is false).
- `lane = lead.x` (line up exactly behind).
- `a.speedLimit = a.target*profile.pace*1.06` — hard-clamped: `a.speedLimit=Math.min(a.speedLimit,a.target*profile.pace*1.06)`.
- When `a.draftTime>=1.8` and `leadGap<12`, force `tactic='overtake'` on that tick and reset `a.draftTime=0` → the pop-out.

Guardrails: `director.encounter==='recover'` still forces `yield` (that assignment stays last in the tactic chain, as today). The 6 % boost is the only speed-cap exception in this spec, is tied to a ≤1.8 s window, and applies to *closing on someone ahead* only — it can never be used to chase a player who is behind.

> Existing-test note: in `adaptive.test.mjs`'s 1000-step loop the rival passes the fixed-`s` player within the first second (`v≈31`), so `a.draftTime` expires long before `v` asymptotes to `42.8`; `v` converges from below and never overshoots `target*pace`. Re-run `npm test` after implementing and, if `a.v<=42.8` ever trips, drop the multiplier to `1.0` and keep slipstream purely positional.

### A.2 Tactic `block`

*Feel:* distinct from `defend` (which mirrors `p.x`). `block` **anticipates** — it moves to the side the player is already drifting toward and gets there first, with a rate limit so it reads as a racing move, not a snap.

Trigger:
```js
const ruthless=profile.style==='ruthless'||profile.style==='aggressive';
const canBlock=gap<0&&gap>-22&&ruthless&&(director.encounter==='pressure'||director.encounter==='duel')&&p.health>55&&a.stun===0;
```
Effect (replaces `defend` when true):
```js
const drift=Math.sign(p.vx||0)||(p.x>path.x?1:-1);
lane=clamp(p.x+drift*1.9,path.x-5.5,path.x+5.5);
a.speedLimit=Math.min(a.target*profile.pace,Math.max(0,p.v*1.02));
```
Guardrails: requires `p.health>55` (never blocks a hurt player), is unreachable under `recover` (which forces `yield`), and the speed limit is *capped to just above the player's speed* so a block can never turn into a brake-check. The existing lateral rate limiter (`desiredVX` clamp ±4.6, `vx` slew ±8·dt) is untouched, so the rival physically cannot teleport into the player.

### A.3 Tactic `bait`

*Feel:* the rival claims the clean lane beside an upcoming hazard and sits alongside, squeezing the player toward the dirty line.

Requires the hazard list. Extend `avoidHazards` rather than `controlRival` (it already owns hazard state and already runs after `controlRival` for road rivals):

```js
export function avoidHazards(a,hazards,p,director){
 const next=hazards.find(h=>h.s>a.s&&h.s-a.s<38&&Math.abs(h.x-a.x)<h.width*.5+1.2);
 const bait=hazards.find(h=>h.s-a.s>14&&h.s-a.s<58&&Math.abs(h.x-p.x)<h.width*.5+2.6);
 if(!next&&bait&&(director.encounter==='pressure'||director.encounter==='duel')&&Math.abs(p.s-a.s)<14&&p.health>45&&director.encounter!=='recover'){
  const side=bait.x>=0?-1:1;                    // clean side of the hazard
  a.tactic='bait';a.lane=clamp(bait.x+side*4.4,-6.8,6.8);
  a.speedLimit=Math.min(a.speedLimit||a.target,Math.max(8,p.v+1));
  return;
 }
 if(!next)return;
 /* ...existing body unchanged... */
}
```
Guardrails: disengages automatically the moment the rival itself has a hazard ahead (`next` wins), requires `p.health>45`, and only ever occupies **one** side of a 4-lane road, so the player always has an open line. Never active under `recover` (the existing `recover` branch of `avoidHazards` still takes priority for the rival's own hazard).

### A.4 Encounter `duel`

*Feel:* the race narrows to one-on-one. One rival is nominated the duellist and gets a faster think rate plus access to `block`/`slipstream`; the others hold station and are barred from striking.

Detection lives in the survey pass (§B) and is surfaced as `field.duel` (rival index or `-1`). `Director.update` gains an optional 5th parameter:

```js
update(p,dt,remote,vmax=80,field=null){
 ...
 const duelReady=!!field&&field.duel>=0;
 const desired = p.health<32||p.time-this.damageAt<5 ? 'recover'
   : this.remoteUntil>p.time&&(this.requested!=='duel'||duelReady) ? this.requested
   : duelReady&&this.cleanTime>5 ? 'duel'
   : this.cleanTime>9-(this.aggression||0)*3&&p.v>vmax*.45 ? 'pressure'
   : 'balanced';
 ...
 this.notice = desired==='recover'?'RIVALS BACKING OFF / RECOVER YOUR LINE'
   : desired==='pressure'?'RIVALS PUSHING / WATCH YOUR MIRRORS'
   : desired==='duel'?(field.duelName||'RIVAL')+' HAS LOCKED ONTO YOU'
   : 'RIVALS REGROUPING';
}
```
`this.duel=duelReady?field.duel:-1` is stored for `controlRival`. Also add `this.aggression=0` and `this.duel=-1` to `reset()`.

Guardrails preserved exactly: the `recover` branch is still first and unconditional; a Laya-requested `'duel'` is rejected unless `duelReady`; the `p.time-this.changed>6` dwell is unchanged. With `field===null` (all existing tests) `duelReady` is false and `9-(this.aggression||0)*3 === 9`, so the branch tree is byte-equivalent to today.

Effect in `controlRival`:
```js
if(director.encounter==='duel'){
 if(i===director.duel)a.think=.08+i*.02;            // duellist reacts fastest
 else{tactic='race';a.speedLimit=a.target*profile.pace*.97}  // pack holds station
}
```

### A.5 Remote-tactic guardrail (mandatory)

`Director.tactic` is applied to *every* rival while `remoteUntil>p.time`. The new tactics must be filtered per-rival so Laya can never impose a tactic whose preconditions are false:

```js
export function guardTactic(tactic,a,p,director,profile,gap){
 if(director.encounter==='recover')return 'yield';
 if(tactic==='block'&&!(gap<0&&gap>-22&&p.health>55&&(profile.style==='ruthless'||profile.style==='aggressive')))return 'defend';
 if(tactic==='slipstream'&&!(gap>3.5&&gap<17))return 'race';
 if(tactic==='bait')return 'race';   // bait is chosen locally in avoidHazards only
 return TACTICS.includes(tactic)?tactic:'race';
}
```
Call it wherever `director.tactic` is consumed: `let tactic = director.remoteUntil>p.time ? guardTactic(director.tactic,a,p,director,profile,gap) : /* local chain */`.

## B. Multi-rival coordination

One pre-pass per frame, O(n) plus one `n log n` sort of a 3-element index array. No all-pairs work; per-rival lookups are O(1) array indexing.

### B.1 New export in `src/rivals.js`

```js
const BANDS=5;
export function bandOf(x,flight){const half=flight?28:6.8;return Math.max(0,Math.min(BANDS-1,Math.round((x+half)/(2*half/(BANDS-1)))))}

export function surveyRivals(rivals,p,dt,field={}){
 const n=rivals.length;
 field.n=n;
 field.claims=field.claims||[];field.claims.length=n;
 field.aheadOf=field.aheadOf||[];field.aheadOf.length=n;
 field.side=field.side||[];field.side.length=n;
 field.close=field.close||[];
 field.band=field.band||new Int8Array(BANDS);field.band.fill(-1);
 field.order=(field.order&&field.order.length===n?field.order:Array.from({length:n},(_,i)=>i));
 field.order.sort((x,y)=>rivals[y].s-rivals[x].s);          // leader first, n log n
 field.leader=field.order[0]??-1;
 field.strikeLock=Math.max(0,(field.strikeLock||0)-dt);

 let duel=-1,duelBest=0,striker=-1,strikerGap=Infinity;
 for(let k=0;k<n;k++){
  const i=field.order[k],a=rivals[k===0?field.order[0]:i],r=rivals[i];
  // nearest actor ahead of r: the rival one place up in the order, or the player if closer
  const up=k>0?rivals[field.order[k-1]]:null;
  const playerAhead=p.s>r.s?{s:p.s,x:p.x,v:p.v}:null;
  field.aheadOf[i]=(up&&playerAhead)?(up.s<playerAhead.s?{s:up.s,x:up.x,v:up.v}:playerAhead)
    :(up?{s:up.s,x:up.x,v:up.v}:playerAhead);
  field.claims[i]={x:r.lane??r.x,s:r.s};
  field.side[i]=(r.x>=p.x?1:-1);
  // sustained-proximity duel timer
  const near=Math.abs(r.s-p.s)<11&&Math.abs(r.x-p.x)<4.2&&Math.abs((r.y||0)-(p.y||0))<3;
  field.close[i]=near?(field.close[i]||0)+dt:Math.max(0,(field.close[i]||0)-dt*1.5);
  if(field.close[i]>6&&field.close[i]>duelBest){duelBest=field.close[i];duel=i}
  const g=Math.abs(r.s-p.s);
  if(g<strikerGap&&(r.stun||0)===0){strikerGap=g;striker=i}
 }
 field.duel=duel;field.striker=striker;
 return field;
}
```
`field.duelName` is set by the caller (`main.js`) from the personality table, so `rivals.js` needs no HUD knowledge.

### B.2 Lane-claim de-confliction (inside `controlRival`)

After `lane` has been chosen and before the traffic-avoidance loop:

```js
if(field&&field.band){
 const b=bandOf(lane,a.flight),owner=field.band[b];
 if(owner>=0&&owner!==i&&Math.abs(field.claims[owner].s-a.s)<16){
  // someone nearer the front already owns this band — mirror to the far side
  lane=path.x-(lane-path.x);
 }
 field.band[bandOf(lane,a.flight)]=i;
}
```
Because `main.js` iterates rivals in `field.order` (leader first — see §H.2), the lead rival always wins the band and trailing rivals resolve around it. Deterministic, no oscillation, one array write and one read per rival.

### B.3 Pincer under `pressure`/`duel`

When two or more rivals are within 30 m of the player and the encounter is `pressure` or `duel`, the survey-assigned `field.side[i]` forces complementary flanks instead of both piling onto the same line:

```js
if(field&&(director.encounter==='pressure'||director.encounter==='duel')&&tactic==='overtake'&&Math.abs(gap)<30){
 lane=p.x+field.side[i]*2.8;
}
```
`field.side[i]` is derived from the rival's *current* x each frame, so a rival never crosses through the player to reach its flank.

### B.4 Shared strike authority (`main.js`)

Replace the hardcoded `i===0` striker test:

## C. Personality expansion

Append two archetypes; indices 0–2 and their exact numbers are untouched.

```js
export const PERSONALITIES=[
 {name:'VIPER',style:'aggressive',lane:-4,pace:1.07},
 {name:'GHOST',style:'technical',lane:0,pace:1},
 {name:'ECHO',style:'patient',lane:4,pace:.95},
 {name:'SABLE',style:'ruthless',lane:-2,pace:1.04},
 {name:'KITE',style:'draft',lane:2,pace:.97}
];
```

**SABLE / ruthless** — the late-braker. It is the only archetype that unlocks `block` (§A.2) outside of VIPER, it refuses to `yield` until the Director's `recover` guardrail forces it, and it tolerates hazards longer: in `avoidHazards`, `style==='ruthless'` scales the braking distance down (`(next.s-a.s)*.72` instead of `*.9`) so it dives later into dirty lanes. Feel: it doesn't race you, it leans on you.

**KITE / draft** — the shadow. Lowest raw pace of the fast group (.97) but its trigger window for `slipstream` is widened (`leadGap<22` and `draftTime<2.6` for this style only) and its pop-out is committed (`overtake` held for a full two think ticks via `a.draftTime=-0.4` on exit, which suppresses re-drafting). Feel: invisible for ten seconds, then suddenly level with your front wheel.

**Indexing changes — every call site (grep-verified, exactly three):**
1. `src/rivals.js` `controlRival`: `const profile=PERSONALITIES[i%3]` → `const profile=PERSONALITIES[a.pi??(i%PERSONALITIES.length)]`.
2. `src/rivals.js` `DecisionClient.tick`: `PERSONALITIES[i].style` → `PERSONALITIES[a.pi??(i%PERSONALITIES.length)].style`.
3. `src/main.js` `hud()`: `PERSONALITIES[i].name` → `PERSONALITIES[a.pi??(i%PERSONALITIES.length)].name`.

Add a roster helper and a module-scope rotating counter (plain number — **not** localStorage, no DOM):
```js
export function rosterFor(count,seed=0){
 const out=[];for(let k=0;k<count;k++)out.push((seed+k)%PERSONALITIES.length);return out;
}
```
In `main.js`, module scope: `let rosterSeed=0;` and in `initializeActors()`:
```js
const roster=rosterFor(3,rosterSeed);rosterSeed=(rosterSeed+1)%PERSONALITIES.length;
rivals=Array.from({length:3},(_,i)=>({...existing fields...,pi:roster[i]}));
```
Each race fields a different trio of the five; `a.pi` is absent in every existing test, so `i%PERSONALITIES.length` keeps index 0 → VIPER, pace 1.07 (the `42.8` assertion in `adaptive.test.mjs`).

## D. Session-adaptive difficulty

### D.1 Where it lives
New pure class in `src/rivals.js` (no DOM, plain-Node importable), instantiated **once** at module scope in `main.js` (`const skill=new SkillTracker()`), never serialized, never written to `localStorage`. It is deliberately not reset by `start()` — only by page reload.

```js
export class SkillTracker{
 constructor(){this.rating=0;this.races=0}
 record({place=1,total=4,wrecked=false,distance=0,time=1,vmax=80,crashes=0}){
  const placeScore=wrecked?-1:((total-place)/Math.max(1,total-1))*2-1;        // 1st=+1, last=-1
  const ratio=Math.min(1.2,distance/Math.max(1,time)/Math.max(1,vmax));
  const speedScore=Math.max(-1,Math.min(1,(ratio-.62)/.18));
  const crashScore=Math.max(-1,Math.min(1,1-crashes/6));
  const perf=Math.max(-1,Math.min(1,placeScore*.5+speedScore*.3+crashScore*.2));
  this.rating=Math.max(-1,Math.min(1,this.rating+(perf-this.rating)*.35));
  this.races++;return this.rating;
 }
 get paceScale(){return 1+this.rating*.06}                // [0.94, 1.06]
 get aggression(){return Math.max(0,Math.min(1,.5+this.rating*.5))} // [0, 1]
}
```

### D.2 Signals
`place` and `wrecked` already exist in `main.js:finish()`; `distance=p.s`, `time=p.time+hitStopDebt`, `vmax=p.flightUsed?bike.vair:bike.vmax`. `crashes` is new: add `let crashes=0` at module scope, `crashes++` inside `collision()` on the `if(impact(...))` true branch, and `crashes=0` in `start()`.

In `finish()`, after the existing records block (do **not** touch `neon-rash-v3-records`):
```js
if(setup.mode==='race')skill.record({place,total:rivals.length+1,wrecked,distance:p.s,time:p.time+hitStopDebt,vmax:p.flightUsed?bike.vair:bike.vmax,crashes});
```

### D.3 How it scales rivals
Applied **only at race start**, so difficulty never shifts mid-race (and the in-race speed cap stays encounter-independent, preserving the `adaptive.test.mjs` "without increasing speed limits" assertion):
- `initializeActors()`: `target:((air?bike.vair*.74:bike.vmax*.84)+i*(air?2.4:1.9))*skill.paceScale`
- `start()`: after `director.reset()`, set `director.aggression=skill.aggression;`
- `director.aggression` feeds exactly two thresholds: the pressure clean-time gate (`9-aggression*3` → 6–9 s, §A.4) and the overtake commit distance in `controlRival`: `gap<(director.encounter==='pressure'?90:38+(director.aggression||0)*10)` → 38–48 m.

### D.4 Bounds proof
`paceScale ∈ [0.94,1.06]` ⇒ road rival target ∈ `[0.79·vmax, 0.89·vmax]` — always below the player's attainable top speed, so a perfect player can always win; at the floor the rivals are still within ~20 % of the player, so the race is never a walkover. `aggression ∈ [0,1]` only shifts timing thresholds, never speed. `rating` is hard-clamped `[-1,1]` and moves by at most 0.35 of the gap per race, so two bad races cannot collapse the difficulty and one lucky race cannot spike it.

## G. Explicit rejections

1. **Rubber-band catch-up speed for trailing rivals.** Would require raising `speedLimit` above `target*pace`, directly breaking the `a.v<=42.8` invariant, and it is the single most commonly hated racing-game mechanic. Adaptive difficulty is applied between races instead (§D).
2. **Persisting the skill rating to `localStorage`.** The only existing game key is `neon-rash-v3-records` (leaderboard) plus `neon-rash-setup`; adding a third hidden key that silently changes difficulty across page loads is an invisible, un-debuggable state machine. Per-session only, as instructed.
3. **Rival-vs-rival collision physics.** O(n²) per tick, and pile-ups ahead of the player are unavoidable-collision generators — a direct fairness-guardrail violation. Rivals continue to pass through each other; the band claim system (§B.2) makes that visually rare.
4. **Laya choosing a rival index, a lane, or a numeric aggression value.** Any of these makes the model semi-authoritative over geometry and would need its own validation surface; `systemOne` is a *choice* API, and each extra field costs inference latency inside an already 900 ms-abort budget. The model stays advisory over two enums.
5. **Per-rival Laya requests.** Triples request rate against a single-in-flight service and gives the model no more information than the batched `rivals[]` array already carries.
6. **A fourth "swarm"/"ambush" encounter.** `duel` already covers the missing texture; each new encounter multiplies the Director's branch matrix and the dwell-time interactions that `adaptive.test.mjs` pins.
7. **Giving rivals real `BIKES` physics instead of the scalar `target`.** Interesting, but it is a rewrite of `controlRival`'s motion model, an order of magnitude over the stated budget, and it would invalidate every tuned constant in CHANGELOG 3.2.0.
8. **Anything from ROADMAP §5–8** (new worlds, bikes, hazard types, progression, multiplayer, mobile). Out of scope; `WORLDS.length===4` stays asserted.
