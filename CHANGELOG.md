**The project is renamed from Neon Rash to Yoru** (github.com/mdsa3d/yoru) and relicensed from MIT to **Apache-2.0** (see LICENSE, NOTICE; third-party MIT/CC0 components keep their own licenses — both are Apache-compatible). ## 3.19.1 — 2026-10-03
- Real-GPU bench follow-up (Apple M4 Pro, Chrome/ANGLE Metal, DPR 2, 1728×962 — `neon-rash-bench-1791016481777.json`): baseline p50 9.8 / p95 12.8 ms, fxaa 8.3, gtao 15.6, ssr 28.6 (p99 54), shadows 10.7, tunnels p50 13.0 but **p99 70.1**, dither 14.1 (+4.3 ms for a trivial pass), and `refreshHz:102` while `quality.hz` reported 60. Root causes found from code and fixed:
- **Tunnel hitch — light-count shader recompiles (confirmed in vendored r180 source):** the tunnel interior `PointLight` was toggled via `.visible` (`world.js`). r180 collects lights with `traverseVisible` and bakes `numPointLights` into the program cache key, so one visibility flip recompiles **every lit material in the scene** — and objects outside the camera/visibility window at that moment still compile lazily when they first appear, so the hitch repeats. The light now stays visible forever with `intensity 0` when unused (pure `tunnelLightLevel(enc,effects)`, Node-tested; constant light count, no recompile on entry/exit or on garage-flag toggles), and a new `World.warmup()` (`renderer.compile(scene,camera)`) runs after `setWorld()`/`setActors()` so first-use program compilation happens at load, not mid-race. GPU-side effect is not Node-testable (CLAUDE.md render exception) — re-measure with `?bench=1`.
- **Dither cost — extra full-res MSAA hop (confirmed code path; magnitude GPU-dependent):** the dither was a separate terminal `ShaderPass`; enabling it forced one more full-resolution round trip through the 4×MSAA HalfFloat composer target (three.js resolves the multisampled framebuffer via `blitFramebuffer` whenever such a target is sampled) at ≈5.1 Mpx (DPR 2, ratio cap 1.75). The dither is now **merged into the grade shader** as a uniform-gated branch (`uDither`): zero extra passes, zero extra resolves, identical palette/Bayer math. Side effect, stated: when FXAA is on (samples 0) the dither now applies *before* FXAA instead of after — visually negligible. The separate `DITHER_SHADER`/pass is gone; `ditherPalette`/`bayer8` exports and the ladder's dither rung are unchanged.
- **Refresh-rate mismatch — stale snapshot + too-strict cadence gate (confirmed / likely):** (a) `bench.js` captured `quality:game.quality` once at result-object construction, i.e. the boot default — the JSON now reads it after the run. (b) `estimateHz()` required p95 ≤ 1.35×p50; a live 240-frame game window always contains a few hitches and ProMotion varies its cadence, so the gate never accepted on real hardware and `displayHz` — and therefore the ladder's frame budget — stayed at the 60 Hz default on a 102 Hz panel (a 9.8 ms p50 looked like "headroom" at a 16.7 ms budget). The gate is now p95 ≤ 1.6×p50 + 4 ms (still rejects genuinely unstable windows, tested) and the **measured** rate is used unsnapped (90–125 Hz → e.g. 102 → 9.8 ms budget, never forced to 60).
- **Tunnels bench methodology fixed:** the tunnels config was the only one that parked the bike (throttle released, v=0, static camera) — on a ProMotion display the measured window collapsed to ~27 fps average (110 frames/4 s) despite a 13 ms p50, consistent with macOS demoting the refresh of static content (likely cause of the extreme p99; ProMotion policy is not observable from code). The config now teleports to 60 m before the mouth at v=50 with the throttle held and **drives through the tunnel**, like real gameplay; each rep re-teleports to the same approach point.
- **Bench repeats:** every config now runs `reps` times (default 3, override `?benchReps=`) after one warmup; the JSON reports the median-by-p50 run's p50/p95/p99 plus `p50Min`/`p50Max` spread per config and the raw `runs` array, so single-run noise is visible. Config order unchanged. Full bench ≈ 100 s at defaults.
- New tests: 9 — `quality.test.mjs` +2 (hitch-tolerant `estimateHz` accept/reject incl. the exact 9.8/12.8 ms M4 Pro window; ladder budget follows a measured 102 Hz cadence and demotes on the real tunnels window), `bench.test.mjs` 4 (`summariseRuns` median-run selection, even-count upper median, percentile-ordering invariant, order independence), `tunnel-light.test.mjs` 3 (level mapping purity/clamping/effects gate, continuity across a real zone mouth — no threshold that could reintroduce a toggle). Full suite: **152/152 in the node:20 container** (143 baseline). Browser: `previews/bench-smoke.cjs` and `tests/browser-v3-smoke.cjs` pass under SwiftShader (software rendering — **not hardware evidence**; the tunnels/dither/hz fixes must be re-measured on a real GPU with `?bench=1`).

## 3.19.0 — 2026-10-03
- Adaptive quality ladder (`src/quality.js`, pure/DOM-free, Node-tested): the old p50-only `adapt()` with hardcoded 60 Hz thresholds (23/17 ms), which shed *resolution first* and dropped every effect at once at scale ≤ .8, is replaced by an 8-rung ladder that sheds expensive features first and resolution last: GTAO → shadow resolution/refit (2048+re-fit → 1024 fixed box) → road detail maps → dither suppression → MSAA 4×→0 (FXAA takes over, per the existing `setSamples()` contract) → render scale .85 → .6 with the composer bypassed at the floor. SSR is nowhere in the ladder: it stays experimental, default off, `quality==='high'` only, and is never auto-enabled.
- Hysteresis, not thrash: the frame budget derives from the **measured display refresh** (rAF cadence via pure `estimateHz()`; 60/120/144 Hz get proportional budgets, default 60 Hz until a stable cadence is seen). Decisions use p95 with a p99 hard-spike term, never p50 alone: demotion needs 2 consecutive slow windows (p95 > 1.25×budget, or p99 > 2.2×budget), promotion needs 3 consecutive headroom windows, every move is exactly one rung followed by a 2-window cooldown, and an isolated spike changes nothing. On vsync-pinned displays (deltas quantised to the interval) "headroom" is p95 ≤ 1.12×budget, so strong GPUs on 120/144 Hz panels can still recover rungs even though their deltas can never fall below the vsync interval.
- Initial GPU capability probe (main.js, hint only): reads the `WEBGL_debug_renderer_info` unmasked renderer when available plus maxTextureSize, devicePixelRatio, `navigator.deviceMemory`/`hardwareConcurrency` and coarse-pointer. Known discrete/Apple Silicon start at the top rung; **unknown or masked renderers start mid-high (rung 5/7), never MAX**; integrated/mobile/software rasterisers start at rung 2. The string matching is an explicit heuristic (commented as such in `src/quality.js`) and only picks the starting rung — the measured ladder corrects a wrong guess within seconds of real frame data.
- Manual quality honoured exactly: `high`/`low` apply the historical fixed presets (manualSettings in `src/quality.js`, unit-tested) and never consult the ladder; the per-feature `gfx*` Garage flags still gate individually on top (a flag fully disables its feature; the ladder rung only ever *caps* auto mode). The `setSamples()` dispose-and-rebuild contract on the two composer render targets is unchanged. The performance HUD now shows the current rung (`MAX 7/7`, `MID-SHADOW 5/7`, … or the manual preset) plus the estimated refresh rate.
- Bench mode `?bench=1` (`src/bench.js`, loaded only in bench mode): cycles baseline / +FXAA / +GTAO / +SSR / +shadows / +tunnels (teleported to the first tunnel zone, as gfx-shots did) / +dither for fixed durations (defaults 1.2 s warmup + 4 s measured, override with `?benchMs=`/`benchWarmup=`) in the standard race-start scene with a fixed camera mode, manual `high` quality so the ladder never interferes, then exposes the result as `window.__bench` and downloads `neon-rash-bench-<ts>.json` with the GL renderer string, DPR, resolution, estimated refresh and p50/p95/p99 per config. **No real-GPU numbers are claimed or shipped: the harness was only smoke-run under SwiftShader software rendering in the container (`previews/bench-smoke.cjs` → `previews/bench-swiftshader.json`), which proves it executes end to end but whose timings are NOT hardware evidence.** Per-GPU numbers (M4 Pro, 5070 Ti, integrated/mobile) must be measured by running `?bench=1` on those machines.
- New tests: 10 (`tests/quality.test.mjs`) — ladder ordering (expensive-first, resolution-last, SSR absent), weak-GPU monotone convergence to the floor without oscillation, strong-GPU vsync-locked climb to MAX, isolated-spike tolerance vs sustained-slowness demotion, one-rung-at-a-time recovery with cooldown, 120 Hz and 144 Hz budgets, manual preset fidelity, `estimateHz` accept/reject cases, `probeTier` vendor/integrated/software/coarse-pointer cases. Full suite: 143/143 in the node:20 container.
